# ADR-011: Устойчивость к ограничениям доступа из РФ

- Статус: принято
- Дата: 2026-08-25
- Связанные: этап 2 (compose), ADR-001 (образ vLLM), ADR-009 (HF-модели)

## Контекст

Доступ к Docker Hub / PyPI / HuggingFace из РФ нестабилен. При этом заранее городить зеркала —
преждевременное усложнение: скорее всего официальный доступ будет работать.

## Решение

**Дефолт — официальные источники.** План Б активируется только при фактической недоступности,
переключением переменных окружения `.env`, **без правок кода и compose-файлов**:

| Что | Переменная | Дефолт |
|-----|------------|--------|
| Registry для образов | `APP_DOCKER_REGISTRY` (префикс, пусто = Docker Hub) | *(пусто)* |
| HuggingFace | `HF_ENDPOINT` (напр. hf-mirror.com) | официальный |
| PyPI | `PIP_INDEX_URL` | официальный |

Правило: любая внешняя загрузка (образы, pip, модели) идёт через конфиг, а не литералы в коде.

## Trade-offs

| Критерий | Зеркала заранее | Реактивно через env (наш выбор) |
|----------|-----------------|--------------------------------|
| Сложность старта | Выше (поиск/проверка зеркал сразу) | Нулевая |
| Рассинхрон версий образов | Риск | Только при переключении |
| Готовность к блокировке | Высокая | Средняя — но план описан и дёшев |

## Последствия

- Положительные: нулевые затраты пока доступ есть; переключение на зеркало = одна строка в `.env`.
- Отрицательные / риски:
  - при блокировке потребуется время на подбор рабочего зеркала — здесь фиксируем проверенные:
    *Docker Hub: зеркала подбираются по факту; HF: `https://hf-mirror.com`; PyPI: `https://pypi.org` (офиц.) / альтернативы по факту*;
  - тяжёлый образ vLLM — главный риск: если Docker Hub недоступен, рассматриваем предзагрузку
    образа архивом (`docker save/load`) как обходной путь.
