# ADR-003: Векторная база данных

- Статус: принято
- Дата: 2026-08-25
- Связанные: ADR-007 (ACL pre-fetch через payload filter), ADR-009 (размерность эмбеддингов)

## Контекст

Хранение эмбеддингов чанков корпуса RusLawOD с обязательной **pre-fetch фильтрацией по clearance**
(критерий приёмки задания: User B не должен получить SECRET-контент). Нужны: нативные метаданные-
фильтры, работа в docker-compose, HNSW-поиск, лёгкая эксплуатация на одной машине.

## Решение

**Qdrant** — одна коллекция `chunks`, в каждом point payload:
`{act_id, title, chunk_no, clearance}`; фильтр `clearance ∈ allowed(role)` применяется до поиска.

## Trade-offs

| Критерий | Qdrant | Milvus | Weaviate |
|----------|--------|--------|----------|
| Фильтры по payload (для ACL) | Нативные, быстрые (filterable HNSW) | Есть, тяжелее | Есть, гибридный синтаксис |
| Зависимости в compose | Один контейнер | etcd + MinIO + … (тяжело) | Один контейнер |
| Ресурсы | Низкие (Rust) | Высокие | Средние |
| Quantization (память) | Scalar/PQ из коробки | Есть | Есть |
| RBAC open-source | Базовый (API-key) | Есть | Ограничен |

Milvus отклонён: оверинжиниринг для MVP (зоопарк зависимостей ради фич кластера, которые не нужны).
Weaviate — запасной вариант: хорош, но у Qdrant проще и предсказуемее фильтрация + ниже потребление
ресурсов. RBAC хранилища не используем ни в одном случае — доступ контролирует backend (ADR-007).

## Последствия

- Положительные: pre-fetch ACL выражается одним `Filter`-условием; снапшоты коллекции для бэкапа;
  лёгкий контейнер для minikube-этапа.
- Отрицательные / риски:
  - clearance живёт денормализованно в payload каждого чанка — при смене метки акта нужен
    повторный upsert его чанков (принято: метки меняются редко);
  - размерность векторов фиксируется выбором bge-m3 = 1024 (см. ADR-009).
