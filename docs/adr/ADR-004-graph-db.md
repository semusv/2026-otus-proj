# ADR-004: Графовая база данных

- Статус: принято
- Дата: 2026-08-25
- Связанные: ADR-006 (онтология), ADR-007 (ACL на узлах графа)

## Контекст

GraphRAG требует graph DB для онтологии `Act / Authority / Topic / Concept` и расширения контекста
на 1–2 hop от найденных актов. Нужны: Cypher-подобный язык, UI для наглядной демонстрации графа
на защите, работа в docker-compose, свойства узлов под метки clearance.

## Решение

**Neo4j Community Edition** (последняя стабильная, образ из Docker Hub).

## Trade-offs

| Критерий | Neo4j Community | NebulaGraph | Memgraph |
|----------|-----------------|-------------|----------|
| Язык запросов | Cypher (стандарт де-факто) | nGQL (свой) | Cypher |
| UI для демо (Browser) | Отличный, из коробки | Слабее | Есть |
| Распределённость | Нет (CE) | Да | Нет |
| RBAC встроенный | Нет в CE (только EE) | Есть | Нет |
| Ресурсы / простота | Низкие | Высокие (3 сервиса) | Средние |
| Экосистема Python | Зрелая (`neo4j` driver) | Меньше | Средняя |

NebulaGraph отклонён: распределённость не нужна на объёмах MVP, эксплуатация сложнее.
Важно: в CE нет встроенного RBAC → clearance фильтруем сами через свойства узлов + WHERE
(см. ADR-007); это осознанный компромисс.

## Последствия

- Положительные: Browser UI — эффектная часть демо (виден путь по графу); Cypher читаемый,
  тесты пишутся легко; зрелый драйвер.
- Отрицательные / риски:
  - безопасность графа полностью на совести backend (запросы строим параметризованно);
  - CE не масштабируется горизонтально — приемлемо для учебного MVP.
