# ADR-007: Security / RBAC

- Статус: принято
- Дата: 2026-08-25
- Связанные: ADR-003 (payload filter Qdrant), ADR-004 (WHERE в Cypher)

## Контекст

Критический критерий приёмки задания: **User B (viewer) не получает SECRET-документ ни в ответе,
ни в цитатах, ни через расширение графа**. Пользователей MVP — три роли; отдельный IdP избыточен.
Security-by-Design требует фильтрации ДО выдачи данных из хранилищ (pre-fetch), а не после.

## Решение

1. **JWT выпускает сам backend**: `POST /auth/login` → HS256, секрет из `.env`
   (`APP_JWT_SECRET`, fail-fast при отсутствии). Пользователи/роли/сессии/аудит — PostgreSQL.
2. **Роли → clearance**: `viewer → [PUBLIC]`, `analyst → [PUBLIC, INTERNAL]`, `admin → [все]`.
3. **Pre-fetch ACL везде**:
   - Qdrant: `Filter(field=clearance, match any allowed)` — секретные точки физически не участвуют в поиске;
   - Neo4j: во всех Cypher `WHERE n.clearance IN $allowed` — секретные узлы не попадают в expand_graph;
   - цитаты и пути графа формируются ТОЛЬКО из уже отфильтрованного контекста.
4. Keycloak — **rejected alternative**: ещё один тяжёлый сервис ради 3 пользователей MVP;
   OAuth-flow усложняет демо и нагрузочные тесты без выигрыша по критерию задания.

## Trade-offs

| Критерий | Свой JWT на backend | Keycloak | API-keys |
|----------|--------------------|----------|----------|
| Соответствие заданию (auth + RBAC) | Полное | Избыточно | Недостаточно (нет ролей/сессий) |
| Эксплуатация в compose | Нет доп. сервисов | +1 тяжёлый контейнер | — |
| Аудит (кто/что/когда) | В нашей PG (audit_log) | Свои логи | Ограничен |
| Риск ошибиться в безопасности | Средний (простая схема HS256) | Низкий | Средний |

## Последствия

- Положительные: единая точка авторизации; ACL проверяется одним резолвером роли→метки;
  негативные сценарии покрываются pytest+Postman (матрица 3 роли × PUBLIC/INTERNAL/SECRET).
- Отрицательные / риски:
  - безопасность JWT-логина на нас (rate-limit login, bcrypt, короткий TTL токена);
  - при добавлении SSO в будущем потребуется миграция — интерфейс `resolve_clearances(role)`
    изолирует эту точку изменения.
