# ADR-005: Оркестрация агента

- Статус: принято
- Дата: 2026-08-25
- Связанные: ADR-002 (LLM), ADR-006 (инструменты retrieval)

## Контекст

Задание прямо требует: оркестратор агента с явными Memory module / Planner / Tools Interface,
циклы и ветвления (Agent Loop с re-plan). Линейные цепочки (LCEL) не принимаются.
Нужна проверяемая state machine с трассируемыми переходами узлов.

## Решение

**LangGraph**: граф состояний (`TypedDict` state), узлы = функции, рёбра = условные переходы.
Компоненты: `agents/graph.py` (топология), `agents/memory.py` (Memory: история сессии из PG),
`agents/planner.py` (Planner: выбор инструментов), `rag/tools.py` (Tools Interface).

## Trade-offs

| Критерий | LangGraph | LlamaIndex Workflows | LCEL-цепочки |
|----------|-----------|----------------------|--------------|
| Циклы/условные переходы | Явные, first-class | Событийная модель, менее наглядно | Нет (линейно) — отклонено заданием |
| State machine + checkpointing | Да | Ограничено | Нет |
| Трассировка шагов (OTel) | Спаны на каждый узел | Сложнее привязать | Только вся цепочка |
| Тестируемость переходов моками | Хорошая | Средняя | — |
| Порог входа | Выше | Ниже | Низкий |

LlamaIndex Workflow силён в готовых RAG-рецептах, но наш цикл re-plan и выбор инструментов
выражаются в нём менее явно. LangGraph даёт граф как код — читается как схема на защите.

## Последствия

- Положительные: цикл Agent Loop (evaluate → planner, макс. 2 итерации) — одна условная кромка;
  unit-тесты графа без LLM (моки инструментов); каждый узел виден отдельным спаном в Jaeger.
- Отрицательные / риски:
  - API LangGraph меняется между версиями — версия фиксируется в pyproject;
  - состояние графа надо держать сериализуемым (история сессии живёт в PG, не в памяти процесса).
